Getting Started

git clone https://github.com/igaribay/deepbioscientific.git
cd deepbioscientific
git checkout dev
npm install
npm run dev

The dev server starts at http://localhost:5173 with hot module replacement.

Branch Protection (set up in GitHub)

  • Go to Settings > Branches > Add rule for main
  • Enable Require pull request reviews before merging
  • Enable Require status checks to pass before merging
  • Never push directly to main — always go through a PR

Development Workflow

1
Create a feature branch from dev 
git checkout dev
git pull origin dev
git checkout -b feature/update-hero
2
Make your changes and test locally 
npm run dev          # develop with hot reload
npm run lint         # check for lint errors
npm run type-check   # verify TypeScript
npm run test:unit    # run tests
3
Push and open a PR into dev 
git add -A
git commit -m "Update hero section copy and animation"
git push -u origin feature/update-hero

Open a Pull Request on GitHub targeting the dev branch.

4
Preview on Netlify

Netlify automatically generates a unique preview URL for every PR (e.g., deploy-preview-7--your-site.netlify.app). Share this URL with reviewers to preview changes before merging.

5
Merge into dev, then into main

Once approved, merge the PR into dev. When ready to go live, open a PR from dev to main and merge it. Production deploys automatically.

Netlify Preview Setup (One-Time)

1
Go to app.netlify.com and sign in with your GitHub account.
2
Click "Add new site" → "Import an existing project".
3
Select the deepbioscientific repository from GitHub.
4
Set the production branch to dev. Build settings are auto-detected from netlify.toml (build command: npm run build, publish directory: dist).
5
Click Deploy. Netlify will build and give you a preview URL.
6
In Site Settings → Build & Deploy → Continuous Deployment, ensure Deploy Previews is enabled. This generates a unique URL for every pull request.

The repo includes a netlify.toml that configures the build and SPA routing automatically — no additional Netlify configuration needed.

Production Deployment

Production deploys are fully automatic. When code is merged into main:

  1. GitHub Actions runs .github/workflows/deploy.yml
  2. Builds the project with Node 22 (npm ci && npm run build)
  3. Prerenders all routes to static HTML for SEO
  4. Deploys the dist/ folder to the gh-pages branch
  5. Site is live at deepbioscientific.com

Do not manually edit the gh-pages branch — it is auto-generated.

Architecture Overview

Build Pipeline

The production build (npm run build) runs three stages:

  1. Client build — Vite bundles Vue components, CSS, and assets into dist/
  2. SSR build — Separate server-side build into dist-ssr/
  3. Prerender — scripts/prerender.js renders each route to static HTML with page-specific meta tags, then removes dist-ssr/

The result is fully static HTML that hydrates into a Vue SPA on page load — best of both worlds for SEO and interactivity.
